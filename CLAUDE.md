# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Commands

```bash
npm install
npm start      # http://localhost:3000 (SQLite in data/sisroe.db)
npm run dev    # auto-restart on change
npm test       # node:test API suite, in-memory SQLite (TEST_DATABASE_URL=... runs it on PostgreSQL)
```

Syntax-check a file with `node --check <file>`. Requires Node >= 22.13 (uses built-in `node:sqlite`).

## Architecture

Multi-school (multi-tenant) incident log. Express backend + vanilla JS SPA (ES modules, no build step).

- `server/db.js`: one adapter for SQLite (`node:sqlite`) and PostgreSQL (when `DATABASE_URL` is set). Write SQL with `?`
  placeholders; they become `$n` for PG. Use `db.insert` to get the new id, and `db.transacao` for multi-step writes.
  Timestamps are ISO strings created in JS (`db.agora()`), not DB defaults.
- **Tenant rule:** every query on school data MUST filter by `escola_id = req.usuario.escola_id`, including lookups
  of ids that come from the client (tipo_id, turma_id, aluno ids). `test/api.test.js` has isolation tests: extend
  them when adding routes.
- `server/auth.js`: JWT holds `{uid, eid}`. The user is reloaded on every request (deactivation takes effect right away).
  `trocar_senha` blocks everything except `/eu` and `/minha-senha`. Roles: `exigeGestao` (poc/coordenador/vice/diretor),
  `exigeAdmin` (system admin: vice/diretor/master), `exigeDirecao` (Res. 68 decisions + cancel: vice/diretor only),
  `exigeBuscaAtiva`, `exigeGestaoOuAdmin`. `master` = one per school, admin without access to student data; rules in
  `conferirRegrasMaster` (escola.js).
- `public/js/catalogo.js`: shared by server and browser: categories, MACROS (a–j), REGRAS_BO, default steps
  (`PROCEDIMENTOS`, used when a type has no own steps; keys stored in `ocorrencias.protocolo`), roles, labels.
- `server/protocolo179.js` is GENERATED from the Protocolo 179 PDF (see `ferramentas/LEIAME.md`): 50 situations with
  lettered steps. `server/tipos.js` seeds them per school and updates them. Each occurrence stores a snapshot of its
  steps in `ocorrencias.passos`; `GET /tipos` is light, `GET /tipos/:id` returns steps.
- Frontend: `app.js` hash router loads `telas/<name>.js`, each exporting `render(el, params)`. The CSP forbids inline
  scripts and handlers: wire events with `addEventListener`. Always pass user content through `esc()`.
- Res. SEDUC nº 68/2026 (indisciplina): administrative checklist = Art. 7º I–X; `ocorrencias.nivel` (Art. 5º, Nível III
  requires `analise_inicial`); `data_conhecimento`, `manifestacao_estudante`. `routes/medidas.js` holds the afastamento
  preventivo rules (admin only, Nível III, ≤5 dias letivos, one extension ≤ initial with Conselho date + family notice)
  and the Art. 15 report data. New columns go in `MIGRACOES` in `db.js` (ALTER TABLE, errors ignored).
- Hosting: `api/index.js` + `vercel.json` (Vercel serverless: static `public/` served by the CDN, `/api/*` goes to the
  Express app; set `PG_MAX_CONEXOES=1`) and `render.yaml` (Render free web service). DB is Neon (PostgreSQL).
  `db.init()` runs on every cold start and must stay idempotent and race-tolerant.
- Guia de registro: `telas/guia.js` (`#/guia`), images in `public/img/guia` regenerated by `ferramentas/capturas-guia.mjs`
  (fictitious school). Re-run it when the Nova ocorrência screens change.
- Chat/avisos: `routes/chat.js` (chat per occurrence, same visibility as the occurrence; `/notificacoes` is polled by
  `public/js/notificacoes.js` every 45 s for pop-ups; Web Push via `server/push.js` only when VAPID keys are set, and
  push text never includes student names). PDF: `server/pdf.js` (pdfkit, Helvetica/WinAnsi — `limpo()` sanitizes text).
- SED import: CSV parsed in the browser (`public/js/sed.js`), rows sent to `POST /alunos/importar-sed`; RA matched with
  `LTRIM(ra,'0')`. Carômetro photos are resized client-side and stored in `fotos_alunos` (no persistent disk on Vercel).
  `POST /alunos` (any role but master) adds a student missing from the list, RA optional (`incluido_por`/`incluido_em`);
  SED and pasted imports fill the RA of a same-name student without RA instead of duplicating.
  Carômetro files (PDF/JPG ≤20 MB): `routes/carometros.js`, stored base64 in `carometro_partes` and sent/fetched in
  ~2.8M-char parts (Vercel 4.5 MB request/response limit); one per turma (new replaces old). Batch photos:
  `casarFoto` in `public/js/imagem.js` matches file names to RA/name, then `PUT /alunos/:id/foto`.
  Busca ativa: `routes/busca.js` (access = `PERFIS_BUSCA`: gestão + agente, gerente, secretaria; not professor); WhatsApp only opens `wa.me` links (`public/js/whatsapp.js`), never sends by itself.
- Integrity rules: the original relato is never edited (use notas), gravidade only goes up, ocorrências are cancelled
  (with a reason), never deleted.
